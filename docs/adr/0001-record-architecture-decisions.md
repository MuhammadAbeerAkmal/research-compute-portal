# 1. Record architecture decisions

Date: 2026-11-25

## Status

Accepted

## Context

Decisions about tools and design are easy to forget, and later it is unclear why something was built a certain way.

## Decision

Important decisions are written down as short Architecture Decision Records (ADRs) in `docs/adr/`, using the format of this file: context, decision, consequences. ADRs are numbered and not edited after they are accepted. If a decision changes, a new ADR replaces the old one.

## Consequences

- The reasoning behind the design stays visible in the repo.
- Writing an ADR takes a few minutes per decision.
